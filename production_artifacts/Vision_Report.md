# Vision Report: Explainable Hybrid GraphRAG for Conversational Recommendation (Master's Thesis)

## 1. Objectives and Strategic Vision (The Vision)
The target architecture represents a definitive shift away from legacy predictive recommendation algorithms toward a dynamic, context-aware conversational agent. The system addresses the fundamental limitations of pure LLM implementations (hallucinations, lack of deterministic grounding) and traditional engines (cold-start problem) by synthesizing **Multi-Agent orchestration**, **Hybrid GraphRAG retrieval**, and **explicit Knowledge Graph reasoning**.

The strategic vision of this project prioritizes Explainability, Groundedness, and Conversational Fluidity, ensuring every recommendation generated by the agent is transparent, verifiable, and logically sound. While the core pipeline leverages strong zero-shot/few-shot LLM reasoning and pre-trained dense embeddings, **targeted model training (including RL/IRL dialogue policy networks, GNN/GCN graph representations, learned score-fusion/reranking models, or parameter-efficient fine-tuning) is explicitly permitted and supported whenever empirical evidence shows it improves recommendation accuracy, multi-turn preference elicitation, or dialogue efficiency.**

## 2. User Experience (UX) and System Behavior
* **Natural Conversation**: A chat-based interface (e.g., built with Chainlit/Streamlit). The user does not feel like they are manually querying a database; instead, they interact with an expert advisor by describing implicit needs (e.g., "I'm looking for a laptop for computer science studies that can handle newer games").
* **Active Clarification**: If a query is too general, the system does not guess. The agent autonomously determines when to seek clarification, asking targeted questions to refine the user's constraints and update their profile.
* **Explainability (XAI) & Data Provenance**: Every presented recommendation transcends black-box suggestions. It contains a fact-based justification explicitly derived from the Knowledge Graph's topology, connecting the user's historical preferences directly to the recommended target.

## 3. Core Engine Logic
The project moves away from rigid processing pipelines and pure Text-to-Cypher generation in favor of a modern **Multi-Agent System (MAS) + Hybrid GraphRAG** paradigm.

1. **Multi-Agent Orchestration (Router & Critic)**: 
    * **Orchestrator**: The central cognitive engine that classifies user intent to dictate the dialogue policy. It autonomously decides whether to seek clarification, update the persistent user profile, or initiate a retrieval sequence.
    * **Critic**: A specialized agent that evaluates retrieved candidates against the nuanced, soft constraints of the user's prompt prior to final generation, ensuring strict adherence to the user's implicit desires.
2. **Entity-Based Memory Architecture (MemoCRS)**: Moving beyond the noisy concatenation of raw dialogue history, the system utilizes a User-Specific Memory bank. It stores discrete, extracted entities and user attitudes, allowing for targeted semantic retrieval of relevant historical context across sessions without context-window degradation.
3. **Hybrid Semantic-Structural Retrieval**: 
    * **Vector Search**: Natural language intents are embedded into dense vectors for rapid Approximate Nearest Neighbor (ANN) search via Neo4j Vector Indexes.
    * **Structural Filtering**: Semantic results are simultaneously and deterministically filtered using hard Cypher constraints (e.g., price boundaries, brand exclusions) parsed dynamically by the Orchestrator.
4. **Response Generation with Explicit Reasoning**: By injecting explicit graph reasoning pathways into the LLM's context window, the model is architecturally constrained to generate responses rooted in demonstrable data provenance.

## 4. Key Architectural Decisions & Scope Definition
To guarantee the successful execution and focus of the master's thesis, the project scope is rigorously defined:
* **Pragmatic & Targeted Model Training (Training Allowed When Beneficial)**: Rather than an arbitrary ban on model training, the project adopts a **pragmatic hybrid policy**: we start with modular Prompt Engineering, Hybrid GraphRAG retrieval, and pre-trained dense embeddings as a strong, interpretable foundation, **and we actively employ custom model training (e.g., Deep RL / IRL policy networks for multi-turn dialogue management, GCN / LightGCN / BPR graph embeddings, Learning-to-Rank fusion weights, or LoRA adapters) whenever a necessity arises and training provides measurable gains for our system.**
* **Single-Dataset Graph Construction & Unified Baseline Strategy**: The project utilizes the **Amazon Reviews 2023 dataset** exclusively. By dropping the LLM-REDIAL dependency, we ensure a perfect 1:1 comparison against classic recommendation baselines (Matrix Factorization, Content-Based, Sequential models) which will be trained and evaluated on the exact same Amazon dataset splits. The graph will be populated with rich structural (Products, Brands, Categories) and lexical (Review Chunks) nodes directly from Amazon data.
* **Knowledge Graph as Grounding**: The system relies on the graph structure to completely prevent LLM hallucinations. The system cannot invent a product or its features.
* **Primary Academic Contribution**: The thesis will academically demonstrate how the integration of Hybrid GraphRAG retrieval and Multi-Agent verification significantly enhances recommendation accuracy, groundedness, and user-perceived explainability compared to both baseline LLM retrieval methodologies (Vector-only, Cypher-only) AND classic recommendation models (Collaborative Filtering, Content-Based) evaluated on the exact same dataset splits.

## 5. Metrics and Evaluation (How do we measure success?)
Evaluating conversational recommender systems (CRS) requires a dual-dimensional approach based on modern research standards:

### A. Recommendation Quality (System Dimension)
* **NDCG@K (Normalized Discounted Cumulative Gain)**: Evaluating the ranking quality delivered by the Hybrid Search mechanism.
* **Hit Rate (HR@K) / Recall@K**: Verifying if the target (correct) item is present in the top-K items retrieved from the database.

### B. Conversation Quality (LLM-as-a-Judge Evaluation)
We will use an advanced LLM model to evaluate the generated responses according to criteria from state-of-the-art CRS frameworks:
* **Coherence**: Does the system properly follow the user's intent and maintain a logical conversation flow?
* **Explainability**: The system's ability to provide clear, detailed, and verifiable justifications for *why* a given product fits the user's preferences based on explicit graph paths.
* **Groundedness**: Measuring the extent to which the response relies *exclusively* on data and relationships fetched from the Knowledge Graph (strictly penalizing attribute hallucinations).
* **Recoverability**: The system's ability to refine and correct its outputs based on negative user feedback or shifted preferences.

### 📅 2026-10-22-026: Release R3.2 — Domain-Agnostic Hybrid Product-Type Matching & W3C SKOS `alt_labels` Induction (`RS-24`)
**Context**: Following Release R3.1, an empirical target-admission audit across the 105 retrieval tuning queries (`evaluations/benchmarks/benchmark_v2.json`) revealed that 13 of 105 target products (12.4% overall; 10 of 21 legacy queries = 47.6%) were hard-rejected by the Cypher category filter due to four mechanisms: (1) accessory-modifier taxon hijacking (`Laptop` $\to$ `Laptop Accessories`, `Tablet` $\to$ `Tablet Accessories`, `Phone` $\to$ `Phone & Tablet Accessories`), (2) irregular morphology blindness (`Mouse` $\neq$ `Mice`), (3) single-taxon collapse (`k=1` amputating parallel device branches such as `Chargers & Adapters` vs `Power Adapters`), and (4) hard-filter cliffs on seller-miscategorized listings (e.g., Samsung Galaxy S20+ in `samsung_tradein`). Furthermore, only 4 of 1,183 `:Taxon` nodes had prototype `t.alt_labels` populated and `ResolverService` did not yet query `t.alt_labels`.
**Decision**:
1. **Full-Catalog W3C SKOS `alt_labels` Induction (`R3.2-D1`)**: Upgrade `scripts/enrich_taxons_skos.py` (enforcing head-noun integrity so accessory taxa never steal bare device nouns, and removing token-reduplication/brand noise) and execute it across all 1,183 `:Taxon` nodes in Neo4j, persisting `t.alt_labels` and `graph_versions/v2/taxon_skos_alt_labels.json`.
2. **Dual-Side Morphological Normalizer & SKOS-Aware `ResolverService` (`R3.2-D2`, Principle P-9)**: Wire `t.alt_labels` into `ResolverService`, apply dual-side morphological lemmatization (`WordNetLemmatizer` + deterministic irregulars/invariant plurals) and head-noun vs. modifier decomposition, and cap accessory-head taxa at $0.45$ when no accessory was requested.
3. **Multi-Taxon Family Shortlist Resolution (`R3.2-D3`)**: Expand category resolution from `k=1` to a cohesive family of matching `Taxon` nodes (`resolve_category_family`, up to 6 taxa with score $\ge 0.85$), incorporating query-refined sub-types.
4. **Guarded Lexical Head-Noun Escape Hatch & Multi-Path Taxon Consensus (`R3.2-D4`, `R3.2-D5`)**: Admit miscategorized products whose title matches the lemmatized product-type head noun and does not match the accessory-trap exclusion pattern (`case/cover/cable/mount/protector ... for/compatible with/fits ...`), and evaluate minimum taxonomic tree distance across all paths in the resolved `Taxon` family.
**Rationale**: Achieves 100% target admission (105/105) on the tuning split while remaining 100% domain-agnostic (transferable to Fashion, Cosmetics, Movies, Home via SKOS graph data and general morphological normalization).
**Status**: ✅ Accepted (User-approved 2026-10-22)

### 📅 2026-10-21-025: Release R3.1 — Attribute IDF Rarity Weighting (RS-03), Graded Taxonomic Distance (RS-10), and Filter-First Adaptive Search Order (RS-07)
**Context**: Following Stage 1 (`GV2-07` .. `GV2-09`), empirical analysis revealed two critical retrieval bottlenecks:
1. The `attribute` channel was dominated by high-frequency generic attributes (e.g., `Color=Black` on 44,265 products, 16.7% of the catalog), creating massive tie blocks in RRF and crowding out rare, high-precision technical specifications (e.g., `GaN`, `144Hz`, `Mechanical`).
2. Category filtering remained binary (pass/fail), treating sibling categories (e.g. `Floorstanding Speakers` vs `Bookshelf Speakers`) identically to distant accessory traps (e.g. `Speaker Wall Mounts`).
3. For very small Taxon subtrees ($< 500$ products), global vector ANN search risked candidate starvation prior to Cypher filtering.
**Decision**:
1. **Attribute IDF / Rarity Weighting (`RS-03`)**: Scale attribute similarity by normalized inverse document frequency: $\text{score} \times \frac{\log(1 + N / (1 + \text{deg}))}{\log(1 + N)}$, strongly prioritizing rare technical specifications and dampening generic colors/materials.
2. **Graded Taxonomic Proximity (`RS-10`)**: Compute tree distance from candidate `Taxon.path` to target `Taxon.path` via common ancestor depth: distance 0 (exact leaf/descendant) gets factor 1.0; distance 1–2 (siblings) gets factor 0.85; distance 3–4 (cousins) gets factor 0.70; distance $\ge 5$ (distant/out-of-domain) gets factor 0.20 or filter exclusion.
3. **Adaptive Filter-First Search Order (`RS-07`)**: For selective subtrees ($< 500$ products), invert search order to Cypher filter-first, evaluating 100% of candidates in the subtree to guarantee recall against ANN truncation.
**Rationale**: Transforms the attribute channel from a generic noise source into a precision finder, enables graceful substitution without accessory pollution, and eliminates candidate starvation in long-tail categories.
**Status**: ✅ Accepted


### 📅 2026-10-20-024: Stage 1 Graph v2 Structural & Lexical Consumption — Taxon Subtree Filtering, BROADER MACS Relaxation, and Lexical RRF Channel (GV2-07 .. GV2-09)
**Context**: Release R2b tuning on live Graph v2 exposed a critical recall cliff ($HR@20$ collapsing from $90.5\%$ on legacy queries to $9.52\%$ on $S_0$–$S_4$). Empirical investigation confirmed that GraphSearchTool was querying legacy Graph v1 `BELONGS_TO_CATEGORY` and `Category.SUBCATEGORY_OF` relationships which do not exist in Graph v2. This caused 100% of category-filtered products to fail the graph condition and fall back to title matching, which failed on title-blind benchmark queries. Furthermore, Graph v2's prebuilt online `product_fulltext_index` and 1,183-node `Taxon` tree were unconsumed by the retrieval engine.
**Decision**:
1. **Taxon Hierarchy Consumption (`GV2-07`, `RS-24`, `RS-10`)**:
   - Re-route `ResolverService.resolve_category` to match against the 1,183 `:Taxon` nodes (Tier 1 exact, Tier 2 word-boundary regex, Tier 3 in-memory vector projection).
   - Update `GraphSearchTool._build_filters` to match `(:ParentProduct)-[:IN_TAXON]->(leaf:Taxon)-[:BROADER*0..7]->(ancestor:Taxon)` matching leaf or ancestor, with title fallback restricted to products without `IN_TAXON`.
   - Upgrade MACS category relaxation: when candidates $< 3$, query `(child:Taxon)-[:BROADER]->(parent:Taxon)` to generalize one taxonomic level before dropping the category filter.
2. **Online Lexical Channel in RRF (`GV2-08`, `RS-03`)**:
   - Add `product_fulltext_index` as the 4th MaxP retrieval channel (`lexical`) in `score_fusion.py` and `GraphSearchTool`, with Lucene query sanitization.
   - Define fusion presets `rrf4` (equal weights), `wrrf4` (`0.35 product, 0.20 attribute, 0.15 review, 0.30 lexical`), and `cc4`.
3. **Subtree Selectivity-Based ANN Sizing (`GV2-09`, `RS-07`)**:
   - Leverage `Taxon.product_count` to detect selective categories ($< 5,000$ products) and dynamically scale ANN oversampling factor `ann_k_per_limit` to prevent candidate starvation before Cypher post-filtering.
**Rationale**: Restores end-to-end structural alignment with live Graph v2, eliminates the title-blind recall cliff, introduces high-precision lexical retrieval for technical queries, and enables principled taxonomic constraint relaxation.
**Status**: ✅ Accepted

**Rationale**: Preserves backward compatibility with R1/R2a schemas while restoring discriminating power to bias metrics on Graph v2 and grounding all 5 retrieval strata in actual Graph v2 distributions.

### 📅 2026-10-19-018: Graph v2 — Rebuild of the Knowledge Graph from the Raw Amazon Reviews 2023 Electronics Files
**Context**: 104,281 of the 265,307 v1 products are ghosts: they have no title, price or category, and an embedding of the blank template that is identical across ghosts. There are three causes:
- metadata and reviews were sampled independently (`AmazonDataProcessor.process_and_save_data`);
- `scripts/graph_ingestion/batch_ingest.py` created products from reviews (`MERGE`);
- `src/knowledge_graph/graphdb/backfill_embeddings.py` embedded empty texts.

Research report: `production_artifacts/Research_Report_Graph_Rebuild.md`.
**Decision**:
1. **Source** (K-1): `datasets/raw/meta_Electronics.jsonl` and `datasets/raw/Electronics.jsonl` (SHA-256 in `datasets/raw/SHA256SUMS`), plus the official splits. No download.
2. **Catalogue** (K-3): the 265,307 v1 `parent_asin`s, frozen as a hashed ID list and filled from raw metadata. Products are created only from metadata, never from a review. Zero ghosts.
3. **Reviews** (K-11, K-12, G-6):
   - (user, parent_asin) pairs in valid or test are excluded;
   - then at most 20 per product, ordered by `helpful_vote` DESC, `verified_purchase` DESC, `timestamp` DESC, `review_id` ASC;
   - `timestamp`, `helpful_vote`, child `asin` and `in_train_split` are stored on `Review`.
4. **Schema** (G-3, K-7, G-11):
   - v1 labels and relationships keep their v1 semantics: `Category` = `main_category`; `HAS_BRAND` from `coalesce(store, details.Brand)`, with case-only duplicates reported, not merged; `HAS_ATTRIBUTE` for Material, Color, Style and Size; no `numeric_value`.
   - The category tree is built from the raw category lists as `(:Taxon {taxon_id = full path})-[:BROADER]->(:Taxon)` and `(:ParentProduct)-[:IN_TAXON]->(:Taxon)` (deepest level).
   - Listing text is stored as `p.features` (list) and `p.details_json`.
   - A full-text index covers title, description and features.
   - Legacy `Variant`, `Product`, `PriceRange`, `RATED` and `REVIEWS` are dropped, and `Variant`/`PriceRange` are removed from `src/llm_interface/prompts/graph_cypher_prompt.py` (G-12).
5. **Load** (G-1, G-2): a Python transform to CSV with a lineage file, then `neo4j-admin database import full` into a new Docker volume (Neo4j 5.14 Community, G-10), with the v1 volume retained.
6. **Embeddings and indexes** (G-4, G-5):
   - Embeddings are written online with the v1 templates, in deterministic order, skipping empty texts.
   - The top 5 reviews per product (same ordering) are embedded.
   - K-6 (features text in the product embedding) is deferred to an R3 arm (`p.embedding_feat`), with no rebuild.
   - Vector indexes are created in procedure form (5.14 has no `CREATE VECTOR INDEX`), followed by the full-text index.
7. **Memory** (G-7): heap 4G during the build with a raised transaction timeout. At runtime, 2G heap and 2G page cache inside the 8 GB Docker VM.
8. **Validation and citability** (G-8):
   - A validation gate checks zero ghosts, referential integrity, split exclusion, the cap, no blank-template embeddings and indexes online.
   - A `GraphVersion` node is written only after the gate passes.
   - `src/evaluation/provenance.py` records it, and a run against a graph without it is not citable.
9. **R2b amendment of 2026-10-18-014** (G-9): stratum S1 "cold" (no reviews) has about 13 candidates on v2. It is redefined as review-sparse (1–2 reviews in the graph), and true cold start is simulated by masking reviews at query time.
**Rationale**: The KG can only ground what it contains. A rebuild that is a pure function of hashed inputs is reproducible, and the importer enforces referential integrity structurally. Keeping v1 semantics isolates the data fix from representation changes. Data-validation practice: Breck et al., SysML 2019; Schelter et al., 2018.
**Impact on vision**: Strengthens §4 (KG as grounding, Amazon-only) and §5 (reproducible evaluation). All retrieval figures are re-baselined on v2. No model training.
**Approved by**: User (2026-10-19, `/implement` graph v2 Gate #1, G-1 … G-12)

### 📅 2026-10-18-015: R2 Evaluation Protocol — Frozen Split, Paired Statistics, Constraint Satisfaction, RS-02 Rule, Citable Runs
**Context**: R1 arms differed on 2 of 21 queries. With so few discordant queries, no paired test can reach significance (an exact sign test needs at least 6 discordant queries all favouring one arm). Run-to-run LLM extraction noise (CLARIFY counts 0 / 4 / 5) is as large as the effects being measured. Both R1 manifests record `git_commit 989c1cd`, but the evaluated code ran uncommitted and was committed later as `99b8506`. `evaluations/` is git-ignored.
**Decision**:
1. **Split**: hashed, grouped and stratified (`sha256(salt + parent_asin) mod 100 < 60` → test, within each stratum). Legacy-21 goes to tuning. The benchmark SHA-256 and salt are committed. `--split test` requires explicit confirmation and is logged. All tuning, prompt iteration and arm selection happen on the tuning split. The test split runs once per release.
2. **Statistics**:
   - The primary metrics are per-query reciprocal rank and NDCG@10, compared with a paired randomization test or paired bootstrap.
   - HR@K is reported with Wilson CIs and an exact McNemar test.
   - The primary comparisons are pre-registered, with Holm correction across the remaining arms.
   - End-to-end claims use r = 3 repeated runs.
   - Every aggregate states its denominator (all queries / SEARCH-only / cross-run intersection).
3. **constraint-satisfaction@K**:
   - Checked against `gold_constraints` taken from the utterance, never from the target. The current target-derived `structured_filters` are not gold.
   - Price, brand and numeric-attribute verdicts are satisfied / violated / unknown, and unknown is never counted as violated (P-2).
   - Reported as `cs_sat`, `cs_viol`, `cs_unk`, `cs_known` (judged-only) and `violation_free@K`, against both the gold constraints and the extracted request.
   - Category stays in `type-precision@K`.
   - `popularity-bias@K` is reported as `review-coverage-bias@K`, with a `target_review_embedded` slice.
4. **RS-02 rule** (tuning split): `rrf2` becomes the default if the lower bound of the ΔHR@20 CI (`rrf2 − rrf3`) is at least −0.05 and the review channel alone finds the target in at most 2% of queries. The result is confirmed once on test in R3. The decision holds only for the current 4.7% review-embedding coverage.
5. **Citable runs**:
   - The manifest records `git describe --dirty`, a diff hash of `src/` and `scripts/`, the benchmark hash and split, the resolved LLM model ID, and the Neo4j version and graph counts.
   - Uncommitted changes produce a warning and `citable: false`; `--require-clean` refuses to run.
   - Citable live runs are copied to a git-tracked `evaluations_archive/<run_id>/` (manifest, summaries, per-query JSONL, trace SHA-256).
   - Only archived runs may be cited in the thesis. The R1 runs are archived with their commit field marked unreliable.
**Rationale**: A frozen holdout prevents adaptive overfitting (Dwork et al., Science 2015). Continuous paired tests are the most reliable choice for IR comparisons (Smucker, Allan & Carterette, CIKM 2007; Urbano et al., SIGIR 2019). Multiple-testing control follows Carterette (TOIS 2012). Three-valued constraint verdicts follow judged-only evaluation (Buckley & Voorhees, SIGIR 2004).
**Impact on vision**: Strengthens §5. Claims about retrieval quality become statistically defensible and reproducible, and constraint adherence is measured without inventing evidence. Extends 2026-10-03-008 (versioned runs) and 2026-10-05-001 (live-only) without changing them. Order: R2a (metrics, RS-23, archive), then R2b (benchmark v2, RS-02 evidence).
**Approved by**: User (2026-10-18, `/implement` R2 Gate #1)

### 📅 2026-10-17-013: AFP-002 Implemented via Reciprocal Rank Fusion (Retrieval Score Redesign R1)
**Context**: `GraphSearchTool._execute_hybrid_search` and `_execute_vector_search` (`src/tools/graph_search_tool.py`) union the product, attribute and review vector indexes and rank by `sum(score)` over every matching node (weights 1.0 / 0.8 / 0.9, `k = limit × 30`). A product matched by many attribute or review nodes therefore collects many small scores (hub bias): in `ret_021` the Logitech C920 (`B006JH8T3S`) ranked 253rd. AFP-002 (`production_artifacts/action_items/Proposed_Fix_Vector_Aggregation.md`) was approved with adaptive late fusion, which is non-monotonic: weaker extra evidence lowers a product's score. A brainstorm (`_bmad-output/brainstorming/brainstorm-retrieval-score-relevance-2026-10-10/`) and the R1 research report (`production_artifacts/Research_Report.md`, 2026-10-17) re-examined the method.
**Decision**:
1. **Max per channel (MaxP)**: each channel (product, attribute, review) returns each product once, scored by its best match, ranked after the hard filters. Ties use competition ranking; truncation is deterministic (similarity, then `parent_asin`).
2. **Reciprocal Rank Fusion** (Cormack et al., 2009) is the default fusion: `RRF(p) = Σ_c w_c / (k + rank_c(p))`, `k = 60`, equal weights, computed in Python.
3. **Ablation arms** from the same per-channel lists: RRF over 3 vs 2 channels (review channel off), weighted RRF (0.60 / 0.25 / 0.15, AFP-002's weights), convex combination of min-max-normalised MaxP scores, and the legacy `sum(score)`. No weight or `k` tuning before the R2 tuning/test split.
4. **Soft-preference bonus** is rescaled to the fused-score range (`β × max attainable fused score` per matched preference, default `β = 0.25`).
5. **Telemetry and metrics**: per-channel ranks, similarities and the fused score are recorded per candidate and in `eval_trace`. `scripts/evaluate_retrieval.py` adds `popularity-bias@K` and `type-precision@K`.
6. AFP-002 acceptance criteria AC-002.4 (C920 top-5 for `ret_021`) and AC-002.5 (no hub runaway on `ret_001`) remain as regression checks.
**Rationale**: RRF uses ranks only, so the three indexes need no score calibration, and products found by several channels outrank products found by one. MaxP is the standard passage-to-document aggregation (Dai & Callan, 2019). Bruch, Gai & Ingber (ACM TOIS 2023) show that a tuned convex combination can beat RRF, so CC runs as an arm rather than being discarded.
**Impact on vision**: Strengthens §3.3 Hybrid Semantic-Structural Retrieval and §2 Explainability: the retrieval score now reflects match quality and channel agreement, not text volume, and per-channel ranks make the reason for retrieval traceable. No model training, no new dataset, no change to the router, Critic or KECR. Release R1 of `production_artifacts/action_items/Retrieval_Score_Redesign_Roadmap.md`; later releases R2–R5 need their own decisions (D-2 training, D-3 HyDE correction, D-4 Neo4j 5.14 vs Cypher 25).
**Approved by**: User (2026-10-17, `/implement` Gate #1)
